1. Overview

The API provides a RESTful interface for managing Projects and Tasks.

A Project can have multiple Tasks, while each Task belongs to exactly one Project.

All API responses follow a unified response structure.

Successful Response
{
  "success": true,
  "data": {}
}
Error Response
{
  "success": false,
  "message": "A meaningful error message.",
  "errors": [
    {
      "type": "Validation",
      "message": "Project name is required."
    }
  ]
}

The errors property provides additional error details when applicable.


2. API Endpoints
Projects
GET    /projects
POST   /projects
GET    /projects/{id}
Tasks
POST   /projects/{id}/tasks
PUT    /tasks/{id}
DELETE /tasks/{id}


3. Projects API

3.1 GET /projects

Retrieves all projects.

Request
GET /projects

No request body is required.

Success Response

Status: 200 OK

{
  "success": true,
  "data": [
    {
      "id": "0191a6f2-7c1a-7b32-9c4e-123456789abc",
      "name": "Payment Platform",
      "createdAt": "2026-09-08T10:30:00Z"
    },
    {
      "id": "0191a6f2-7c1a-7b32-9c4e-987654321abc",
      "name": "School Management System",
      "createdAt": "2026-09-08T11:00:00Z"
    }
  ]
}

The endpoint returns project information only. Tasks are retrieved through GET /projects/{id}.


3.2 POST /projects

Creates a new project.

Request
POST /projects
Content-Type: application/json
{
  "name": "Payment Platform"
}
Validation
name is required.
name must not be empty or whitespace.
name must satisfy the defined maximum length.

The id and createdAt values are generated by the server.

Success Response

Status: 201 Created

{
  "success": true,
  "data": {
    "id": "0191a6f2-7c1a-7b32-9c4e-123456789abc",
    "name": "Payment Platform",
    "createdAt": "2026-09-08T10:30:00Z"
  }
}
Validation Error

Status: 400 Bad Request

{
  "success": false,
  "message": "One or more validation errors occurred.",
  "errors": [
    {
      "type": "Validation",
      "message": "Project name is required."
    }
  ]
}

3.3 GET /projects/{id}

Retrieves a specific project together with all tasks belonging to it.

Request
GET /projects/{id}
Success Response

Status: 200 OK

{
  "success": true,
  "data": {
    "id": "0191a6f2-7c1a-7b32-9c4e-123456789abc",
    "name": "Payment Platform",
    "createdAt": "2026-09-08T10:30:00Z",
    "tasks": [
      {
        "id": "0191a6f2-7c1a-7b32-9c4e-987654321abc",
        "projectId": "0191a6f2-7c1a-7b32-9c4e-123456789abc",
        "title": "Implement payment API",
        "completed": false,
        "createdAt": "2026-09-08T10:35:00Z"
      }
    ]
  }
}
Project Not Found

Status: 404 Not Found

{
  "success": false,
  "message": "Project was not found.",
  "errors": []
}


4. Tasks API
4.1 POST /projects/{id}/tasks

Creates a new task under a specific project.

The project is identified through the route parameter.

Request
POST /projects/{id}/tasks
Content-Type: application/json
{
  "title": "Implement payment API"
}

The projectId is not included in the request body because it is already specified by the route.

The id, completed and createdAt values are generated by the server.

Validation
title is required.
title must not be empty or whitespace.
title must satisfy the defined maximum length.
The specified project must exist.
Success Response

Status: 201 Created

{
  "success": true,
  "data": {
    "id": "0191a6f2-7c1a-7b32-9c4e-987654321abc",
    "projectId": "0191a6f2-7c1a-7b32-9c4e-123456789abc",
    "title": "Implement payment API",
    "completed": false,
    "createdAt": "2026-09-08T10:35:00Z"
  }
}
Project Not Found

Status: 404 Not Found

{
  "success": false,
  "message": "Project was not found.",
  "errors": []
}


4.2 PUT /tasks/{id}

Updates an existing task.

The endpoint uses PUT because the request represents an update of the task's mutable properties.

Request
PUT /tasks/{id}
Content-Type: application/json
{
  "title": "Implement payment API",
  "completed": true
}

The following properties cannot be modified by the client:

id
projectId
createdAt



Validation
title is required.
title must not be empty or whitespace.
title must satisfy the defined maximum length.
The specified task must exist.
Success Response

Status: 200 OK

{
  "success": true
}
Task Not Found

Status: 404 Not Found

{
  "success": false,
  "message": "Task was not found.",
  "errors": []
}


4.3 DELETE /tasks/{id}

Deletes an existing task.

Request
DELETE /tasks/{id}

No request body is required.

Success Response

Status: 204 No Content

No response body is returned.

Task Not Found

Status: 404 Not Found

{
  "success": false,
  "message": "Task was not found.",
  "errors": []
}

5. HTTP Status Codes


200 OK	  #Successful retrieval or update
201 Created		#Successful resource creation
204 No Content		#Successful deletion
400 Bad Request		#Invalid request or validation failure
404 Not Found		#Requested project or task does not exist

6. Common API Rules
Resource Identifiers

Project and Task identifiers are represented as GUIDs.

Server-Generated Properties

The following properties are generated by the server:

id
createdAt
Date and Time

All timestamps are represented by UTC.

Unified Response

Every endpoint that returns a response body follows the unified response format:

{
  "success": true,
  "data": {}
}

or:

{
  "success": false,
  "message": "A meaningful error message.",
  "errors": []
}

204 No Content is the exception because the response intentionally contains no body.
